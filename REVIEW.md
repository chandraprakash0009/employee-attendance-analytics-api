# REVIEW.md

## Defects found in `app/main.py`

| #  | Where (function / line)                          | What is wrong                                                                                                                                               | How you'd notice it (test, input, or symptom)                                                             | How you fixed it                                                                                                                |
| -- | ------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| 1  | `compute_late_minutes()`                         | The code floors elapsed minutes before applying the 10-minute grace period.                                                                                 | For a 09:30 shift, punch in at 09:40:01 should produce 10 late minutes, but the original logic returns 0. | Compare elapsed seconds against 600 first, then floor to whole minutes.                                                         |
| 2  | `compute_work_hours()`                           | Python's built-in `round()` uses ties-to-even, not the required half-up rounding.                                                                           | Test a duration whose hours value falls exactly on a half-cent boundary.                                  | Use `Decimal` with `ROUND_HALF_UP` for two-decimal rounding.                                                                    |
| 3  | `compute_overtime()`                             | Overnight shifts and the 30-minute minimum overtime rule can be calculated incorrectly if shift end is treated as occurring on the same date.               | Test a shift from 22:00 to 06:00 with punch-out at 06:29 and 06:30.                                       | Calculate the correct shift-end instant, advance the date for overnight shifts, and count overtime only from 30 minutes onward. |
| 4  | `punch_in()`                                     | Checking for an existing record before inserting is not safe under concurrent requests.                                                                     | Send two punch-in requests for the same employee and attendance date simultaneously.                      | Enforce a unique `(emp_code, date)` index and catch `DuplicateKeyError`, returning HTTP 409 for the losing request.             |
| 5  | `punch_in()`                                     | Using UTC's calendar date instead of the attendance date in IST can assign a punch to the wrong day.                                                        | Submit a timestamp near midnight UTC and compare its IST date.                                            | Convert the timestamp to IST and apply the overnight-shift date rule before creating the record.                                |
| 6  | `punch_in()` / `punch_out()`                     | Timestamps may retain fractional seconds, despite the contract requiring whole-second precision.                                                            | Submit epoch milliseconds containing non-zero milliseconds and inspect stored and returned values.        | Truncate timestamps to whole seconds before calculations, storage and response conversion.                                      |
| 7  | `punch_out()`                                    | In the reviewed file, the overtime calculation references undefined `new_punch_out` and `date` variables.                                                   | Submit a valid punch-out request; the endpoint can return HTTP 500.                                       | Pass the actual punch-out timestamp and attendance date to the overtime calculation.                                            |
| 8  | `create_employee()`                              | A check-then-insert sequence can allow concurrent duplicate employee requests to reach the unique index, potentially producing an unhandled database error. | Submit two simultaneous requests with the same employee code.                                             | Catch `DuplicateKeyError` and return HTTP 409 consistently.                                                                     |
| 9  | `create_employee()`                              | `created_at` is stored as a naive local datetime and is not converted to epoch milliseconds in the response.                                                | Create an employee and inspect the timestamp type and timezone.                                           | Store a UTC-aware datetime and return the timestamp in epoch milliseconds.                                                      |
| 10 | Employee and attendance request models           | Plain string fields do not guarantee strict date and shift-time formats.                                                                                    | Submit malformed dates or shift times such as `2026-2-1` or `9:30`.                                       | Add explicit format validation and return HTTP 422 for invalid input.                                                           |
| 11 | `list_employees()` and other paginated endpoints | Pagination must validate page and page-size limits and calculate totals after applying filters.                                                             | Try page 0, a page size above 100, and a department filter.                                               | Validate pagination parameters and use the same filtered query for counting and retrieving records.                             |
| 12 | Monthly analytics and department summary         | Built-in `round()` does not guarantee the required half-up rounding for reported values.                                                                    | Test values exactly halfway between two decimal results.                                                  | Apply consistent half-up rounding to reported percentages and averages.                                                         |
| 13 | `late_leaderboard()`                             | Ranking in Python does not satisfy the requirement to perform ranking in MongoDB.                                                                           | Inspect the implementation and test a tie at the requested limit.                                         | Use MongoDB aggregation with `$setWindowFields` and `$rank`; apply the limit after ranking so cutoff ties remain included.      |
| 14 | Explain endpoint for attendance listing          | The explain query's sort does not exactly match the real endpoint's sort.                                                                                   | Compare the actual list query with the query passed to `explain`.                                         | Keep filters, sorting and pagination consistent between the real query and its explain version.                                 |
| 15 | Explain endpoint for the late leaderboard        | The explain pipeline omits ranking and the post-ranking limit used by the intended leaderboard.                                                             | Compare its pipeline stages with those used by the actual endpoint.                                       | Make the explain pipeline mirror the real aggregation.                                                                          |
| 16 | Explain endpoint date parsing                    | Invalid months can raise an uncaught `ValueError` in branches that parse dates without validation.                                                          | Submit a month such as `2026-13`.                                                                         | Validate the month format and return HTTP 422 for invalid values.                                                               |
| 17 | Index setup / department-summary explain         | A query filtering only on `joined_on` cannot efficiently use an index whose first key is `department`.                                                      | Inspect execution statistics for a collection scan in the employee portion of the summary.                | Consider adding a separate `joined_on` index if needed to meet the explain-plan requirement.                                    |


## Items reviewed and decided were not defects

| Item                                                            | Why it was not considered a defect                                                                                                                          |
| --------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Unique attendance index on `(emp_code, date)`                   | It is necessary to enforce one attendance record per employee per attendance date and protect against concurrent inserts.                                   |
| Employee code as the first field in the unique attendance index | It also supports queries that filter by `emp_code`; a separate single-field index may be redundant for those queries.                                       |
| Competition ranking for leaderboard ties                        | Ranks such as `1, 2, 2, 4` are correct when tied employees share a rank and the next rank is skipped.                                                       |
| Returning all employees tied at the leaderboard cutoff          | The limit should apply to rank, not arbitrarily exclude employees with the same rank.                                                                       |
| Counting employees with no attendance logs                      | The department summary's employee-based lookup and preservation of employees without matching logs allow them to remain in headcount.                       |
| MongoDB-side filtering and pagination                           | These reduce unnecessary data transfer and avoid loading the entire collection into Python.                                                                 |
| `py_compile` succeeding                                         | It confirms syntax validity, but not runtime correctness; undefined variables such as those in the reviewed punch-out calculation can still cause failures. |
